# Cloud script library

Optional scripts are **not** shipped with the mod. They live on a protected `verified` branch of the repository and are installed
on demand from the *Library* window.

```
branch `verified`
├─ catalog.json                 generated by tools/cloud_catalog.py
└─ community/<id>/
   ├─ manifest.json             id, name, name_ru, author, version, description(_ru), min_urushi, entry
   ├─ init.lua                  entry file (default name)
   └─ ...                       more .lua / .json / .txt / .png / .hlsl / .hlsli (max 32 files, 512 KB each)
```

## Player flow
1. *Library → Refresh list* (the only network request; nothing is fetched automatically).
2. *Install* downloads each file from `raw.githubusercontent.com/Garagoro/Urushi/verified/community/<id>/…`, checks its
   SHA-256 against `catalog.json`, stages it and moves it into `scripts/cloud/<id>/` atomically. A mismatch aborts and keeps the old version.
3. The script is enabled right after install (toggle in the *Library* window), loaded on the next *Reload scripts*, runs **isolated**
   (see [SECURITY.md](SECURITY.md)). *Remove* deletes the folder.
4. `min_urushi` in the manifest blocks installation on older mods.

The updater never touches `scripts/cloud/`. Branch name can be overridden with `[cloud] ref=<branch>` in `urushi_settings.ini`
(for testing a candidate branch).

## Shaders
`.hlsl` / `.hlsli` files of a package are installed to `shaders/cloud/<id>/` (not `scripts/cloud/`), where CarFX is allowed to load from;
they show up in the CarFX shader list as `cloud/<id>/<name>.hlsl`. A package may be **shader-only** (no `.lua`, no `entry`).
`#include` inside a shader can only reach files under `shaders/` (so `carfx.hlsli` works, `../../anything` does not).
Review note: a shader cannot touch files or run code, but a hostile one can hang the GPU (endless loop → driver reset), so test shaders in-game before merging.

## Writing a cloud script
* Entry file `init.lua`. It runs in an isolated environment: the normal API (`ui`, `carx`, `events`, `urushi.register_window`, …)
  is available, `io.open("save.json","w")` writes to `urushi_data/<script>/save.json`.
* Multi-file: `local helper = include("lib/helper.lua")` loads a sibling file from your own folder.
* No network, no process execution, no file creation outside the data folder — by design.

## Maintainer flow
```bash
git switch verified
# review the pull request / copy the reviewed folder into community/<id>/
python tools/cloud_catalog.py          # validates + regenerates catalog.json
git add community catalog.json && git commit -m "add <id> 1.0.0" && git push
```
`python tools/cloud_catalog.py --check` can run in CI on the branch. Protect `verified` (require review, no force push) —
the SHA-256 checks only guarantee that files match the catalog; trust comes from who can change the branch.

## Code
`core/cloud_scripts.{h,cpp}` (catalog parser, installer, path/ID validation), `core/bindings/lua_cloud.cpp` (Lua module `cloud`),
`scripts/main.lua` (loading + isolation), `scripts/system_mod.lua` (Library window: Downloaded tab = toggles, Cloud tab = catalog).
